I just open-sourced an Angular library for 3D graphics.

Yes, there are already Three.js wrappers for Angular. But here's why I built another one:

The existing approach uses a custom Angular renderer. It's clever—your template becomes the scene graph directly. But it comes with trade-offs:

❌ No IDE autocomplete (uses CUSTOM_ELEMENTS_SCHEMA)
❌ No template type checking
❌ Typos only show up at runtime
❌ Custom DevTools behavior
❌ Risk of breaking on Angular upgrades

I wanted something that felt like standard Angular:

✅ Typed signal inputs
✅ Full IDE support
✅ Works in Angular DevTools
✅ Uses only public APIs (upgrade-safe)
✅ Animation behaviors as composable directives

So I built @hive-academy/angular-3d using hostDirectives + signals instead of a custom renderer.

54 components • 24 directives • WebGPU ready • SSR compatible

This is our first release. If you work with Angular and 3D graphics, I'd love your feedback on the API design.

🔗 Demo: https://hive-academy.github.io/angular-3d/
🔗 GitHub: https://github.com/Hive-Academy/angular-3d

Question for Angular devs: When choosing libraries, do you prioritize maximum flexibility or type safety and standard tooling?
